## Warum BIOS bei ALLEN RESPOs ohne Implementierung geht

BIOS ist kein Code, kein Modul, kein Ordner, kein Workflow, keine Technik.

BIOS = ROOT-RECHT = META-STATUS = OBER-PRINZIP = globaler Zustand für ALLE RESPOs

- Jeder RESPO darf BIOS lesen/prüfen/als ROOT akzeptieren
- KEIN RESPO muss BIOS implementieren/laden/verstehen
- BIOS wirkt durch root.yml, nicht durch Technik

## Wie NC BIOS wirklich benutzt

1. STATIC MASTER liest BIOS
2. STATIC MASTER prüft BIOS
3. STATIC MASTER entscheidet REAL / NICHT REAL
4. ENGINE darf nur laufen wenn BIOS = REAL
5. RESPOs folgen automatisch weil ENGINE sie steuert

## BIOS ROOT MAP

BIOS = ROOT
RESPO = STATES = BK / RW / SL / OP
ENGINE = ACTION
STATIC = VALIDATION
OP = USER
TECH = MODULES

BIOS ist Richter. RESPO sind Zustände. ENGINE ist Ausführer. STATIC ist Kontrolleur. OP ist Operator. TECH sind Werkzeuge.

## Frequenz Shift

BIOS = Frequenz-Schicht die alles synchronisiert
STARTER_SHINE = Starter-Shine-Presenter
SHIFT = Frequenzwechsel
